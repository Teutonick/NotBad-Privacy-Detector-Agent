# NotBad Privacy Detector Agent

Для любой находки PrivacyAudit может локально подготовить обезличенный отчёт о неточном определении. Перед открытием публичного GitHub Issue приложение обязательно показывает предпросмотр, скрывает части пути и заменяет точные технические значения диапазонами. Ничего не отправляется автоматически — последний шаг всегда делаешь ты.

На одном компьютере разрешён только один экземпляр приложения. При восстановлении прошлого аудита окно открывается сразу, а загрузка snapshot идёт асинхронно с видимым прогрессом и блокировкой вкладок до завершения.

NotBad Privacy Detector Agent — переносимый локальный инструмент для цифровой археологии Windows. Он помогает разобрать забытые слои компьютера: персональные данные, секреты, учетные данные, старые следы приложений, архивы, фотографии, метаданные и копии файлов — и объясняет, почему находка заслуживает внимания.

## Чем он отличается

Обычная чистилка спрашивает, что удалить. NotBad Privacy Detector Agent сначала помогает понять: **что это, насколько оно открыто и откуда могло появиться**.

- **Не угадывает.** У каждой находки есть путь, категория, сканер, оценка и фактические основания.
- **Расследует по запросу.** File Provenance Analyzer запускается только для выбранного объекта и никогда не добавляется в массовое сканирование.
- **Подстраивается под тебя.** Локальные ИИ-рекомендации учатся по твоим 👍/👎 только на уже рассчитанных признаках PrivacyAudit.
- **Остаётся приватным.** Аудиты, оценки, расследования и модель хранятся на этом компьютере. Нет аккаунтов, telemetry, облачного анализа и фоновой службы.
- **Остаётся переносимым.** EXE ничего не устанавливает и не добавляет в автозапуск. После использования EXE нужно удалить вручную.

### История файлов приложений

Контейнеры Jump List показываются в отдельном агрегированном разделе **«История приложений»**, который становится доступен после аудита. Кнопка **«Проанализировать историю»** по твоему запросу разбирает Automatic/Custom Destinations, объединяет AppID одного приложения, скрывает пустые группы, сохраняет кириллические ANSI/Unicode-пути и сопоставляет объекты с текущими находками. По умолчанию показаны связанные с аудитом строки; историю можно раскрыть фильтрами доступности, сохранения в меню, риска, размера, возраста и поиска — их назначение и варианты объяснены в легенде. Каждый сохранённый объект можно оценить кнопками 👍/👎: общая локальная модель учитывает отдельные признаки истории и позволяет сортировать объекты и приложения по ИИ-приоритету. Приоритет приложения выводится из его наиболее рекомендованных объектов, а не из одной общей оценки контейнера. Для файлов доступны детали, открытие, папка, Корзина и копирование пути; если Windows временно занял буфер обмена, копирование выполняется вне UI-потока с повтором и показывает понятный статус вместо подвисания или падения. Папки открываются напрямую; отсутствующие пути остаются read-only forensic-следами. Онлайн-справочники AppID не используются, данные никуда не отправляются.

Для отчёта о неточности теперь обязательно написать своими словами, что именно не так. Эта просьба стоит первой строкой предпросмотра, а в ссылку GitHub заранее добавляются метки `privacy-audit`, `incorrect-detection` и тип исправления — так отчёты можно сортировать. Публикацию по-прежнему подтверждаешь ты вручную.

## Что можно обнаружить

- персональные данные: имена, email, телефоны в строгом формате, адреса, явные ссылки Telegram и проверяемые идентификаторы;
- секреты и credentials: известные форматы API-токенов, явные присваивания ключей, JWT, приватные ключи, строки подключения и строгие ASCII-кандидаты со смешанным регистром и цифрами;
- остатки приложений: профили, сессии, кеши, историю, логи, настройки и возможные хвосты удалённых программ;
- риски в медиа: GPS/EXIF, серийные номера камер, фото документов с обязательным сочетанием признаков бумаги, строк текста и геометрии, лица и признаки присутствия людей;
- архивы и копии: чувствительные файлы внутри ZIP/JAR/APK-подобных контейнеров, похожие документы и изображения;
- следы Windows: Recent, Jump Lists, ограниченные области файловой системы и другие локальные поверхности раскрытия;
- происхождение: связи с приложениями, реальный формат, соседние файлы, Registry и доступные forensic-следы.

## Как это работает

1. Выбери **Quick**, **Full** или **Custom** scan.
2. Отсортируй находки по риску, категории, возрасту, размеру или **✨ ИИ-приоритету**.
3. Открой «Детали»: там будут оценки, основания и результаты уже выполненных сканеров — файл не перечитывается специально для обучения. Нажми стрелку назад или боковую кнопку мыши «Назад», чтобы вернуться в тот же список и к тому же месту прокрутки.
4. Если нужен контекст, нажми **Исследовать происхождение**. Результат сохранится локально и будет переиспользован, пока файл не изменится.
5. Оцени находки кнопками 👍 или 👎. После достаточного количества сбалансированных оценок локальная модель начнёт поднимать выше то, что обычно важно именно тебе.

Если остановить большой аудит, отмена запрашивается асинхронно — интерфейс продолжает отвечать и рисовать индикатор ожидания. Отдельный спинер показывает, что сканер ещё завершает текущую операцию; после отмены частичный отчёт сохраняется.

Содержимое архивов проверяется только после нажатия **«Инспектор архивов»**. Так обычный аудит остаётся быстрым, а после проверки архивы остаются в общем списке с бейджами критичности найденных записей.

## Локальные ИИ-рекомендации

Это лёгкий бинарный классификатор ML.NET для CPU, а не готовая нейросеть. Он использует только уже рассчитанные числовые и категориальные признаки аудита: например, exposure, возраст, категорию, признаки ПДн и секретов, EXIF/GPS и количество похожих объектов. Оценки, векторы и веса никуда не отправляются. Рекомендация не заменяет Exposure Score, Personal Data Score, Secret Score или Archive Privacy Score. При изменении схемы признаков старая модель автоматически перестаёт использоваться.

## Приватность и безопасность

- обычные аудиты работают офлайн; сеть используется только после явного действия — например, для загрузки необязательной YuNet-модели или открытия ссылки в браузере;
- В Windows Recent могут оставаться реальные ярлыки `.lnk`, хотя исходный файл уже удалён. Аудит помечает такие записи как устаревшие следы и не утверждает, что исходный файл всё ещё существует;
- нет Windows-службы, планировщика, автозапуска, трея и постоянного фонового анализа;
- junction/reparse points по умолчанию не обходятся;
- SQLite хранит метаданные и результаты, а не произвольное содержимое файлов;
- файлы и Registry автоматически не удаляются; перемещение в Корзину требует отдельного подтверждения;
- очистка удаляет только данные приложения и заранее показывает область действия и таймер подтверждения.

## Скачать и запустить

Скачай последний portable `NotBadPrivacyDetectorAgent.exe` из Releases, положи его в удобную папку и запусти. Установка не нужна. Обычного режима достаточно для доступных пользователю каталогов; **перезапуск с правами администратора** нужен только для явной проверки защищённых системных областей.

## Сборка и упаковка

Код продукта находится в `src/PrivacyAudit`, тесты — в `tests/PrivacyAudit.Tests`, а сценарии сборки — в `scripts`. Создаваемые при сборке каталоги `bin`, `obj`, `artifacts` и `dist` намеренно исключены из Git.

```powershell
.\scripts\verify.ps1
.\scripts\package-release.ps1
```

Первая команда запускает тесты, публикует single-file EXE и проверяет запуск/завершение. Вторая создаёт компактный версионный ZIP только с portable EXE, документами для пользователя и лицензирования, файлами лицензий сторонних компонентов и SHA-256. Полная документация проекта и демонстрационная GIF-анимация остаются в исходном репозитории.
