# Architecture — NotBad Privacy Detector Agent

For documentation ownership and README scope, see [Project map — Documentation boundaries](PROJECT_MAP.md#documentation-boundaries). This document is the canonical home for runtime behavior, implementation mechanics and component contracts; product-level summaries link here instead of duplicating these details.

## Privacy-safe diagnostic reporting

Incorrect-detection reporting is opt-in and remains local until the operating system opens the browser. The Core `DiagnosticReportBuilder` requires a 10–1000 character user explanation and places that exact explanation at the top of the preview and pre-filled Issue body. It produces minimal Markdown; no network client or GitHub API is present. Only after the mandatory preview and explicit confirmation does the app open a GitHub `issues/new` URL. GitHub still requires the user to publish the public Issue.

Reports include a structural path such as `USERPROFILE / directory / file.db`, extension, coarse size/exposure ranges, categorical scanner identifiers, application version, and Windows version. They exclude raw metadata, contents, exact paths, filename stems, sizes and timestamps, PII/secret samples, GPS, username, and hostname.

## Startup and snapshot restore

`App` acquires the named local mutex before constructing `MainWindow`; a second process shows a localized informational message and exits. `MainWindow` never deserializes the previous audit in its constructor. After first render it automatically calls `SnapshotStore.LoadAsync` on a worker thread. Progress is shown in the existing busy indicators; tab navigation stays visible while interactive controls are temporarily read-only. The snapshot contains enriched finding metadata plus preset, roots, start/completion timestamps and duration. After indexing, Overview shows the current Privacy Radar summary (database size, audit type/scope/time, finding count and confirmed deep-analysis signals) instead of the new-scan form.

Restore is cancellable and remains non-destructive. `SnapshotStore.LoadAsync` accepts a cancellation token, and `RefreshFindingsPage` treats canceled sorting/dispatcher work as an expected state rather than allowing `TaskCanceledException` to escape from `async void`. During restore, `CancelRestoreButton` is the sole enabled action; clicking it cancels loading, releases the restore task guard immediately, clears only the in-memory presentation and opens the new-audit settings. The previous snapshot and audit rows stay untouched until a valid new Start action is accepted. This lets a user abandon a large restore without waiting for deserialization or accidentally losing the resumable audit.

**Start over** is a two-step transition: it first reveals the normal preset/scope controls without touching the current radar; only a valid click on Start removes the previous resumable snapshot and audit-result rows. Personal ratings, recommendation-model data and exclusions remain separate local knowledge. A completed replacement audit becomes the new radar automatically.

The Overview `Stop` action is visible only while the primary audit scanner is actively running. It is hidden during snapshot restoration, after restoration completes and while the new-audit form is idle; snapshot restoration retains its separate cancel-restore action. The folder picker keeps its path field and enlarged one-line button in the same row.

## Priority deep-check wizard and Triage Router

After a primary audit, Overview prepares a three-state priority wizard on a worker thread. `TriageRouter` reads only existing finding metadata, file existence, names, paths, sizes, dates and header-only image dimensions. It never extracts document text, runs YuNet, calculates entropy or opens archives. Routing produces `(finding, scanner, priority, cost, reasons)` decisions; it answers applicability and queue order, not privacy danger. Demo/default/sample/vendor/cache paths and small images receive soft penalties rather than exclusions. The selected unique scope is at most ten percent of eligible findings and at most 25,000 files, with a weighted operation budget and round-robin diversity across scanner and path/extension clusters.

`IDeepAuditScanner` is the extension contract consumed by `DeepAuditScannerRegistry`. Each registered scanner owns its identifier, localized name, availability check and batch executor. The wizard enumerates registry entries and does not contain scanner-specific branching. The default registry adapts PII, secrets, credential configs, identity traces, archives, document photos, EXIF and people detection. A missing optional YuNet model skips only the people stage; one scanner failure is logged and does not stop later stages.

`PriorityAuditSessionStore` persists only local routing/session state in the app-owned data directory: audit fingerprint, finding IDs, route decisions, completed/skipped/failed route keys, counters and elapsed state. It stores no file contents. Progress is checkpointed during long stages and the regular finding snapshot is saved after each scanner stage. An interrupted running session restores as paused. Pause and cancel preserve completed detector metadata; other mutating controls are read-only during execution while the dispatcher and tab navigation remain responsive.

The dynamic Priority Report tab appears only after the wizard completes. It is backed by the original `Finding` objects and supports confirmed/all/clear/error filters, category/risk/search filters, detection-first/Privacy Risk/date ordering, extended selection, the shared context menu, Details navigation and exact return to its source grid or image tile. Its ✨ AI-priority column and image-tile feedback controls bind to the same `PersonalAttentionScore` / `PersonalAttentionLabel` properties and `PersonalFeedback_Click` persistence path as Findings, so ratings are audit-wide rather than report-specific. For the Images category it exposes the same list/tile switch, thumbnail scale and scale-sensitive pagination as Findings. It contains no deep-scan launch controls.

`PrivacyRadarRanking` maintains two explicit axes. **Objective Privacy Risk** is a 0–100 scanner-evidence score built from original exposure and persisted confirmations such as PII, secrets, credentials, identity traces, sensitive archives, document/ID evidence, people and EXIF/GPS. **Personal Attention** is the independent 0–100 learned probability of user interest. Combined Radar priority uses an 80/20 objective/personal blend and evidence floors for confirmed secrets, credential configuration, identity documents and GPS, so preference cannot bury a confirmed high-impact signal. Findings exposes all three values and Details explains them separately.

The Findings grid presents the two privacy values in one compact `Privacy Risk` column as `Objective | Radar`; the Radar value is blue to indicate the AI/enrichment component. The separate `Detect Risk` column is the local detector severity only. Its default and explicit column sort use `DetectionPriorityRank`: confirmed detections come first, ordered by evidence volume, then category breadth, then the rounded average of the two Privacy Risk values. Scanned-but-clear findings follow, and unscanned `Unknown` findings use only Privacy Risk. If Personal Attention has not been predicted yet, Radar intentionally falls back to Objective, so the pair can be equal. The grid shows modified dates as calendar dates (`yyyy-MM-dd`) without time.

Detection metadata also records which deep scanner completed for each finding. This keeps `Unknown` (not checked) distinct from `No confirmed detections` (checked and clear) after restart; positive badges remain the actual evidence used by the ranking.

After a primary audit, Findings shows a dismissible yellow research hint while no deep detector has completed for the current audit. The hint points to the PII, secrets, credentials/configs, identity, archive and media research actions; it disappears after the first completed deep research or when the user closes it.

The Findings reset action clears ad-hoc filters and search, then restores the fundamental evidence-first `DetectionPriorityRank` order rather than falling back to file modification time. A completed deep scan with no positive result is displayed as `No`; an unscanned finding remains `Unknown`.

Media uses a short page-level description while keeping the detailed independent-process explanation inside its analysis card. Media and Application History headers use the same two-column title/legend layout so the legend button retains its natural width instead of being squeezed into a vertical strip.

NotBad Privacy Detector Agent follows `SCAN → DETECT → CLASSIFY → SIMILARITY MATCH → REPORT`. It does not decide that a file is unnecessary and does not delete files automatically.

## Layers

The shared `MainWindow` modal overlay also hosts onboarding, cleanup, personal-recommendations help, and legal/privacy/third-party document viewers as in-app `UserControl` cards.

The three onboarding slides use local, compact JPG resources (`src/PrivacyAudit/Assets/intro-slide-1.jpg` through `intro-slide-3.jpg`). Each image is shown with a consistent wide aspect ratio; text is constrained to the left content card so the illustration remains visible on the right. No image is downloaded at runtime.
- **Core**: stable models, exposure scoring, discrete size/age/resolution filtering (`FindingFilter`), header-only media dimension reading (`MediaImageInfo`), text extraction (`TextExtractor`), diagnostic crash logger (`CrashLogger`), EXIF metadata extractor (`ExifMetadataExtractor`), document similarity engine (`DocumentSimilarity`), and deep local detectors without WPF dependencies.
  - **CrashLogger**: thread-safe local diagnostic logging to `%LOCALAPPDATA%\NotBadPrivacyDetectorAgent\crash.log` for unhandled UI exceptions, AppDomain faults, and task exceptions.
  - **PiiDetector**: high-performance, timeout-protected C# validator for issuer-aware Luhn payment cards (contiguous digits or conventional four-digit groups), INN (10/12-digit), SNILS, RF passports, emails, strict single-line international phones, Cyrillic FIO, addresses, explicit Telegram links, and PII bundles. Standalone dates are intentionally ignored because they do not establish a birth date without identity context. Short numbers split across lines cannot form a phone, and arbitrary two-digit groups cannot form a card.
  - **SecretDetector**: structured pattern detection (OpenAI, GitHub, AWS, JWT, Slack, Google API keys, DB connection strings, private keys), key-name assignments that require an explicit `=` or `:`, and a high-precision **Shannon entropy** fallback restricted to compact mixed-case ASCII tokens with digits. Prose after words such as `secret`, Unicode text, code identifiers, documentation labels, and duplicate entropy candidates are not reported.
  - **CredentialConfigDetector**: dedicated detector for connection files, authentication profiles, API/registry endpoints, and database/cloud configurations (`.env`, `.npmrc`, `pip.conf`, `NuGet.Config`, `gradle.properties`, `settings.xml`, `docker-compose.yml`, `kubeconfig`, `ssh config`, `git config`, `.pgpass`, `.my.cnf`, VPN configs).
  - **IdentityTraceDetector**: digital archaeology engine aggregating Windows username, machine hostname, and Git author name/email. It checks filenames and supported text/document contents; unsupported binary formats are not decoded as text, preventing embedded build paths such as Python bytecode source paths from becoming identity findings. The ordinary user-profile directory component is not treated as a separate identity signal.
  - **ArchiveInspector**: memory-only inspector for ZIP, JAR, WAR, NUPKG, APK, and archive files analyzing the central directory without disk extraction, identifying sensitive internal files (passwords, passport scans, private keys, `.env`), and computing an Archive Privacy Score.
  - **ExifMetadataExtractor**: pure offline extractor for decimal GPS coordinates (latitude, longitude, altitude), camera make/model/serial number, lens details, software/editor tools, author/artist, last saved by, and creation dates from JPEG/PNG images and Office OpenXML files.
  - **DocumentSimilarity**: lightweight, on-device TF-IDF vectorizer and Cosine Similarity matcher comparing text, markdown, source code, and Office documents against the active audit finding set without requiring external neural network models.
  - **TextExtractor**: bounded memory extraction for plain text, scripts, configurations, and Office OpenXML (`.docx`, `.xlsx`, `.pptx`) using standard ZipArchive.
- **Scanners**: metadata discovery; each scanner is isolated by `ScanCoordinator`.
  - **Application history**: available only after an audit is completed or restored. The separate, user-triggered `ApplicationHistoryAnalyzer` reads OLE Compound File, DestList, and embedded Shell Link records locally with bounded container size, cooperative cancellation, per-container error isolation, ANSI-code-page/UTF-8 path repair, and no referenced-file reads. Known AppIDs that resolve to the same application are merged; empty groups are discarded; unknown applications retain a visible local AppID and are never queried online. Parsed paths are correlated with the in-memory audit index. Existing findings keep their content-derived risk and receive application-history context; only unmatched paths with explicit sensitive-name/extension or UNC evidence can become Medium/High historical findings. Each remembered object has an application-scoped feedback key and can contribute a versioned, content-free history feature snapshot to the shared personal-attention model. Batch prediction runs off the dispatcher; applications aggregate the top three object scores instead of accepting a noisy container-wide label. The workspace legend documents availability, pinned state, audit correlation, size/age, AI ordering and search filters; copying a path retries a busy Windows clipboard on a background STA thread and reports a localized status instead of blocking the dispatcher or allowing an exception to escape.
- **PeopleDetection**: local media vision and perceptual similarity engine:
  - **ImageSimilarity**: on-device perceptual Difference Hashing (`dHash` on $9 \times 8$ grayscale) and Average Hashing (`aHash` on $8 \times 8$ grayscale) computing bitwise Hamming distance similarity scores without neural networks. Invariant to image resizing, JPEG compression, and minor color adjustments.
  - **DocumentDetector**: color saturation filter, substantial neutral paper area, bounded dark-ink density, repeated separated text bands, standard page/card geometry (ID-1 1.58 or A-series 1.41), and exact filename tokens. YuNet faces only corroborate an image that already satisfies the document surface, text, and geometry criteria; a portrait cannot become an ID document from face detection alone.
  - **YuNetDetector**: on-device ONNX face detector.
  - **ImageSafetyClassifier / ImageSafetyScanner**: optional on-device SwiftFormer XS ONNX classification over RGB 224×224 memory-only inputs. Original NSFL, NSFW and SFW scores, argmax class, file identity and model version are persisted in SQLite; unchanged images are reused automatically. Media exposes one strict NSFW filter (`NSFW score > 0.85`) and a right-aligned, background-free eye/eye-off toggle for thumbnail blur.
## Media analysis lifecycle

The Media workspace starts both people and document-photo analysis from the complete found-image collection, independent of the active gallery filter. Candidate discovery, existence checks and YuNet integrity verification run away from the WPF dispatcher; the UI enters a visible preparation state before this work begins. `MainWindow` owns separate cancellation sources and operation sessions for the two analyzers. A pause cooperatively cancels only that analyzer, leaves its completed repository/snapshot results available, and keeps its session so the matching Continue action can resume it. Cancel also preserves completed results but clears only the paused continuation session. Each analyzer has its own progress bar, status text and pause/cancel buttons, so one operation cannot replace the other's state. The people repository persists completed face results per image; document detections are persisted in the finding snapshot as they are produced. EXIF candidate preparation also runs off the dispatcher and remains a separate operation.

Similarity analysis is scoped to the selected finding. Its worker has an independent cooperative pause gate and cancel source; pause/continue does not discard the in-memory candidate position. A completed match list is embedded into that finding's metadata and therefore saved in the regular audit snapshot. Reopening the same object after restart shows the saved matches without recomputing image hashes or document vectors.

- **Storage**: scan metadata and exclusions in local SQLite and snapshot cache.
- **Scoped cleanup**: `AppDataCleanupService` can clear secondary audit/cache data while preserving `ml_feedback` and `Models/Personal`, or delete the exact app-owned local-data root. It rejects any other root and does not traverse reparse points.
- **UI**: explainable findings, thumbnails, dark-themed ToolTips matching the app palette, collapsible **«Legend & Information»** help drawers on workspace views, media preview workspace, intuitive size/age/resolution sliders, emergency «load earlier»/«load more» controls overlaid inside the scroll canvas only after an actual boundary is reached and automatic loading fails, PII, Secrets, Configs, Identity, and Archive scan action buttons, double-click details navigation with a small back-arrow action and browser-style mouse XButton1 return to the captured source list/scroll offset, real-time scan progress indicators, a dedicated cancellation progress state that remains visible until cooperative cancellation completes, **«Reset filters»** actions, EXIF/GPS badges, contextual **«Find similar documents / images»** matching panel with live progress, interactive rating buttons (dim unpressed / bright highlighted pressed states) for the local personal attention model across Findings and Media tabs, Shift/Ctrl extended selection in findings and media lists, a compact RU/EN language switch beside About with persisted local preference and a confirmed restart, and an explicit right-click action that moves selected files to the Windows Recycle Bin after confirmation and removes them from the current audit result.
  - **Sidebar Footer & Promo**: bottom navigation control (`SidebarFooterControl`) featuring multiline text-wrapped global busy indicator spinner card, auto-rotating author projects card (`tnick.cc`, `NotBad Video Wallpaper`, `AI360`, `Filexa TG Bot` with pause-on-hover and URL launch), an **«About»** menu, and an explicit manual update check.
  - **Document Viewer**: self-contained dark offline modal (`DocumentViewerWindow`) reading embedded markdown resources (`DISCLAIMER.md`, `PRIVACY.md`, `THIRD_PARTY_NOTICES.md` with full English & Russian translations).
- **Windows integration**: read-only discovery, Explorer actions and explicit UAC relaunch. Recent `.lnk` entries are inspected as real Windows Recent artifacts; their recorded target is checked without opening it and stale shortcuts are labeled as unavailable targets. Directory findings are explicitly marked and never receive file-open or delete actions.

- **Overview**: summary cards and one-click Custom (selective), Quick, and Full audit presets.
- **Findings**: virtualized list and tile views with risk dropdown, category dropdown, search, discrete size/age sliders, screen exposure toggle, AI-recommendation filter, **«Reset filters»** button, collapsible **«Legend & Information»** drawer explaining every button, slider, and rating, Shift/Ctrl multi-selection, AI-priority ratings (👍/👎/×), and dedicated **«Find personal data»**, **«Find forgotten secrets»**, **«Find credentials & configs»**, **«Find identity traces»**, and **«Inspect archives»** actions with live progress. Archive sensitivity is not presented as an always-empty pre-scan filter: the inspector is the explicit action, and completion automatically selects the localized archive-inspection filter to show archives with sensitive contents and their archive badges. Double-clicking any item navigates directly to object details; directory findings expose only **«Show in Explorer»**, while file findings can be opened or moved to the Recycle Bin after confirmation.
- **Media**: visual image gallery with zoom, discrete file-size/age and centered bidirectional resolution slider (left = below threshold, right = at least threshold), Shift/Ctrl multi-selection, boundary-only emergency batch-loading controls inside the result canvas, **«Reset filters»** button, AI-priority ratings (👍/👎/×), **«Find document photos»** analyzer, **«Scan EXIF & Geolocation»** action, and local people detection scoped strictly to active filtered results. Both sides of the resolution filter read original file-header dimensions lazily; preview dimensions are never used. Dynamic batches capture the first visible tile as a viewport anchor, restore it to the same screen coordinate after collection/layout changes, and suppress loading events until restoration completes, preventing chained page loads. Details keep the original header dimensions even when the visible preview is decoded to a smaller width.
- **Application history**: a dedicated aggregated workspace showing applications and remembered objects rather than `.automaticDestinations-ms` files. Its default view focuses on paths correlated with audit findings; availability, app-menu pinning, risk correlation, size, age, text and AI-priority ordering expose the wider history when requested. Object-level 👍/👎/× controls train the same local recommendation model; applications display an aggregate top-three score and are never rated as one container-wide sample. Existing files open Details on double-click and provide open/show/delete/copy actions; folders open directly and expose only folder/copy actions; missing paths remain read-only forensic traces.
- **Application-history default ordering**: the report ranks entries by forensic availability state first: available and menu-pinned, available and not pinned, missing but menu-pinned, then missing and not pinned. Effective risk, last interaction and path provide deterministic tie-breakers; the optional AI-priority mode remains separate.
- **Incorrect-detection reports**: the local preview requires a free-text explanation of what is wrong, places an uppercase instruction at the top of the report, and pre-fills stable GitHub labels (`privacy-audit`, `incorrect-detection`, plus the selected correction type) for issue sorting. The user still reviews and publishes manually.
- **Details**: full path, timestamps, file size, scanner attribution, exposure rationale, masked PII/Secrets samples, credential & auth parameters, identity trace occurrences, archive internal directory tree with privacy annotations, document geometry scores, extracted GPS & camera metadata, high-resolution media thumbnail preview, contextual **«Find similar documents / images in audit results»** ranking panel with atomic persistence across item selection, and back navigation that returns to the exact source list and scroll position captured at double-click. File findings also expose the same confirmed Windows Recycle Bin action used by list context menus; directory findings never expose it. The navigation accepts the UI arrow, global WPF XButton input, native XBUTTON down/up messages, routed `BrowseBack`, `APPCOMMAND_BROWSER_BACKWARD`, `VK_BROWSER_BACK`, and Alt+Left for mouse-driver compatibility.
- **Sidebar Footer**: integrated offline author promo banner with 4 rotating projects, global active process indicator spinner with wrapped text, and About actions (Disclaimer, Privacy, Third-Party Licenses, GitHub).

Cancellation is cooperative: the current scanner returns accumulated findings and the coordinator stops scheduling later scanners. The cancel button requests cancellation with `CancellationTokenSource.CancelAsync()` so the WPF dispatcher is not synchronously held by cancellation callbacks; an indeterminate cancellation bar remains animated until the active operation has unwound. The UI persists and labels the partial report.

The app owns no background service, scheduled task, startup entry, shell extension or persistent worker. `--smoke-test` constructs the WPF window, reaches dispatcher idle, closes and exits.

Window close cancels every active in-process cancellation source. Optional YuNet and Image Safety HTTPS downloads are the only application model-download paths; each manifest pins an official URL and SHA-256 plus a repository mirror URL. If the official endpoint is unavailable or fails integrity/license validation, `ModelManager` retries the mirror and still requires the same SHA-256 before installation. The checked-in `third_party/` files are unmodified mirrors with adjacent license, source and checksum records and are not bundled into the installer. The update checker only reads the latest GitHub release metadata after an explicit button click and never downloads or installs files. Ordinary audits and personal-model training are offline. A self-contained .NET single-file executable may use the operating system's temporary bundle-extraction cache for native runtime libraries; that cache is runtime-managed rather than application state.

## Manual update check

`GitHubUpdateChecker` performs one bounded HTTPS GET to the project's public `releases/latest` API endpoint only from `SidebarFooterControl.BtnCheckUpdates_Click`. It sends no audit data, paths, identifiers or model state. The running assembly version and normalized release tag are compared locally. A newer version produces a Yes/No prompt; only Yes opens the release page in the default browser. Up-to-date and network-error states are informational and leave the application unchanged.

The priority-audit sidecar belongs to exactly one primary audit fingerprint. More importantly, every accepted new `Scan_Click` resets the in-memory session, persisted sidecar, report collection, wizard dismissal state and navigation tab before scanning starts. This lifecycle boundary prevents a completed report from the previous folder or database from appearing over a new audit even if the settings form was reached by a different UI path.

The priority workflow never presents its budgeted subset as a complete audit. A yellow explanation remains under live progress and in the finished report. Once the report exists, Findings, Media and Application History each show a separately dismissible, scanner-specific reminder directing the user to full-scope manual research. These notices reset with a new audit. Priority Report filtering and sorting produce a stable in-memory result set. `FindingPagination.PresentationPageSize` keeps list pages at 600 rows and applies the shared scale-sensitive tile size only when the Images tile view is active; every filter, presentation or search change resets the report to its first page.

Priority persistence uses `AuditIdentity` (`v2`) derived from immutable audit timestamps. The number of findings is deliberately excluded because deep enrichment can change it. Version-1 `started:completed:count` fingerprints are matched by the timestamp pair and rewritten as v2 on load. `PriorityAuditSessionStore` keeps an atomic `.bak`, considers valid main/temporary/backup documents, and treats `Completed` as terminal within one audit identity so a stale Ready checkpoint cannot hide a finished report. Restore read-only and running-priority locks are composed through one logical-tree pass so collapsed wizard controls are unlocked as reliably as currently visible controls; idle recovery explicitly re-enables Overview navigation when no process token exists. Dashboard cards navigate through the named Findings tab and category tag rather than a positional tab index.

The wizard is a strict state machine: `Preparing → Ready → Running/Paused → Completed`. Starting a new audit invalidates any in-flight preparation generation and immediately hides stale report controls. The offer cannot be dismissed, and both report navigation handlers require `PriorityAuditSession.HasReport`, which is true only for a completed session with routed work. Re-entering Overview reuses the matching in-memory session instead of rebuilding it, while a preparation-generation check prevents an older asynchronous Triage Router result from replacing the current audit state.

On Overview, the primary audit action controls are part of `ScanSettingsPanel`, directly below the preset and folder selectors. This keeps the explanatory Privacy Radar area separate from the controls while preserving the existing visibility and cancellation state transitions during restore and scanning. The primary action pair shares one row; restore cancellation and returning to the previous audit are separate rows with an 8px vertical gap. The directory selector uses the Grid star column rather than a fixed width so long paths do not force the right edge out of the card.

The Overview priority-start CTA is intentionally orange (`#FF9F0A` / `#FFD36A`) to distinguish the guided deep-check entry point from ordinary blue actions.

The completed wizard exposes both the subset Priority Report and a separate **Open FULL report** action that selects the complete Findings tab. Media keeps scanner-specific cards and statuses but omits the redundant analysis heading/subheading; people/document card descriptions are intentionally short so the controls remain compact.

The Media deep-analysis surface owns only an in-memory expanded/collapsed UI state. It starts expanded for each `MainWindow`, collapses its scanner content while retaining a fixed-height chevron target, and never persists that preference with the audit snapshot. The separate Media filter surface is unaffected.

All report-oriented workspaces share the localized accuracy disclaimer: detector signals are informational and must be checked against reality before the user acts. On Findings, Priority Report, Media, and Application History it is placed at the bottom of the corresponding filter/control panel, matching the Findings layout rather than repeating it in the large page header. The completed wizard explicitly restores hit testing and enabled state for both report-navigation buttons so a previous running/read-only state cannot leave them visually present but inert.
# Local personal attention model

The optional AI-recommendation engine is a read-only consumer of `Finding` fields, detector metadata, and already-parsed application-history metadata held by PrivacyAudit. It never opens file content for learning. History rows add application/source categories, availability, pinned/network/audit-match flags, and bounded interaction count/age features; `ItemSource` keeps ordinary findings and historical objects explicit in one model. Numeric/boolean features and ML.NET one-hot encoded categories feed one `SdcaLogisticRegressionBinaryTrainer`. Training requires 20 ratings, 5 per class, and a 20% minority share. Feedback is written immediately, but automatic retraining is debounced for 45 seconds, waits for heavy scanners to become idle, and normally requires 10 new labels. A deep detector immediately batch-rescores changed findings with the current model; rated findings also append bounded feature-evolution events, refresh their stored training features, and queue one idle retraining pass. SDCA uses bounded iterations, convergence tolerance, and light L1/L2 regularization. Every candidate model records a deterministic 20% validation report (accuracy, precision, recall, F1, ROC-AUC, PR-AUC, precision@20, objective-risk baseline@20 and net useful lift) before the final all-sample artifact is atomically installed. Batch prediction reuses one prediction engine and runs off the UI thread. `feature_schema_version` gates stored rows and recommendation artifact loading; only rows matching the current schema participate in training and statistics. Artifacts remain under `%LOCALAPPDATA%\NotBadPrivacyDetectorAgent\Models\Personal` and are never synchronized.

The canonical user-facing explanation is `docs/PERSONAL_MODEL_USER_DESCRIPTION.md` and is mirrored by the localized `PersonalModelInfoText` shown from the Details view. Any algorithm, feature, threshold, persistence/privacy, retraining, score-semantics, or audit-influence change must update both in the same change; a mismatch is a release blocker.

File provenance is a separate, on-demand Details operation. `src/PrivacyAudit/Core/FileProvenanceAnalyzer.cs` never participates in Quick, Full, or Custom scanning: it examines only the selected finding, up to eight parent-directory levels, a bounded sibling set, existing finding metadata, local read-only SQLite schema, executable version metadata, uninstall Registry correlation, and local NTFS Zone.Identifier evidence. It does not claim that an executable created a file without direct evidence. Results and evidence are stored in `file_provenance` and `provenance_evidence`; path, size, modified time, and `FileProvenanceSchema.Version` invalidate stale results. The UI runs it asynchronously with cancellation and offers a manual re-investigation even for unchanged files. A cached result is shown immediately and no new work is performed when Details is reopened.

Local storage has explicit safety limits in `src/PrivacyAudit/Core/StorageLimits.cs`: audit rows and provenance older than 183 days are pruned at startup; diagnostic logs are capped at 10 MiB; the resumable scan snapshot is capped at 256 MiB and an intentionally high theoretical ceiling of 1,000,000,000 findings; personal feedback is capped at 100,000 labels and feature evolution at 250,000 events. If the byte ceiling is reached, the audit itself still completes and SQLite remains canonical, but that oversized snapshot is not replaced. The trained personal model ZIP is not artificially capped because its size depends on the feature schema, not on the number of ratings, and normally remains small.
# In-app modal overlays

All primary user-facing auxiliary panels (onboarding, cleanup confirmation and the local AI-recommendations explanation) are hosted as modal overlays inside `MainWindow`. The overlay dims the active page, captures input, and provides an in-application title bar and close/navigation controls; it does not create another top-level Windows window. Overlay content is implemented as reusable `UserControl` views and is removed from the visual tree when closed, so timers and event handlers stop with the view.

## Optional Image Safety package

`Models/ImageSafety` is independent from `Models/YuNet` but uses the same `ModelManager`, integrity verifier, download progress, license-copy and removal lifecycle. Downloading occurs only after a user click and consent. Image inference is offline and conflicts with people, document-photo, priority and other heavy deep scans. Cancellation keeps completed `image_safety_results`; removing the model does not remove those results. The media-only NSFW blur is a global presentation setting and never creates a derived thumbnail file.
